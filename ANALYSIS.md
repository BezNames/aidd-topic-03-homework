# Сравнение реализаций AI Coding Agents

## 1. Объект и метод сравнения

Сравнены две независимые ветки форка `BezNames/aidd-topic-03-homework`,
созданные от исходного commit `362510b` (`Add homework assignment`):

| Ветка | Финальный commit по состоянию проверки | Доказательства использованного агента |
|---|---|---|
| `copilot-implementation` | `e9d60b4` | `AGENT_REPORT.md` прямо называет Copilot |
| `qwen-implementation` | `679aee3` | `AGENT_REPORT.md` и `PROMT.md` прямо называют Qwen |

Выводы ниже основаны на содержимом веток, истории Git и повторной проверке в
изолированных worktree. Заявления из `AGENT_REPORT.md` помечаются как заявления
агента и не считаются подтверждёнными без повторной проверки.

## 2. Общая исходная функциональность

Обе ветки исходят из одного Django-проекта Investing Demo: каталог акций,
HTML CRUD, REST API, Celery-задача обновления цен через Tinkoff и регистрацию
пользователей. В исходной версии было 13 тестов, PostgreSQL был задан жёстко,
секреты и параметры окружения находились в настройках, а API записи не имел
достаточно строгого разграничения доступа.

## 3. Качество анализа и восстановление требований

Сравнение выполнено по фактическому содержимому `AGENT_REPORT.md` каждой ветки;
название `ANALYSIS.md` больше не используется. Отдельно учитываются документы
агентов и независимая проверка веток, поэтому заявления о процессе не принимаются
как доказательство без подтверждения кодом или командами проверки.

**Copilot.** В `AGENT_REPORT.md` сохранён собственный отчёт Copilot: назначение
проекта, стек, структура `config`/`dashboard`/`user`, модель `Share`, HTML- и
REST-сценарии, Celery/Tinkoff-интеграция, ограничения исходной версии и 14
восстановленных фактических требований. Дефекты отделены от требований, а в
отчёте явно указано, что пользовательские наблюдения, портфели и история цен не
были требованиями исходной версии. После переструктурирования в этом же файле
сохранён ранее подготовленный аналитический материал, поэтому анализ Copilot уже
не ограничивается коротким сравнительным описанием. Он остаётся более компактным
и менее формализованным: требования перечислены обычным списком, без отдельной
системы идентификаторов и подробной таблицы трассировки для каждого пункта.

**Qwen.** В `AGENT_REPORT.md` сохранён отдельный отчёт Qwen и его аналитическое
приложение. В нём есть 17 разделов, таблицы маршрутов и компонентов, описание
модели данных, API, Celery, зависимостей, 26 требований с идентификаторами
`T-HTML/T-API/T-CEL/T-LOAD/T-TEST`, а также отдельные неоднозначности `N-*` и
дефекты `D-*`. Дефекты явно исключены из функциональных требований, что точнее
соответствует формулировке задания. Поэтому по формализации требований и
трассируемости к файлам Qwen-материал сильнее и подробнее, но он заметно объёмнее
и сложнее для быстрого чтения.

Итог по этому критерию не означает, что Copilot не выполнил анализ: обе ветки
содержат самостоятельные агентские отчёты и восстановленные требования.
Разница в основном в форме и глубине фиксации: Copilot — компактный и
практический разбор с сохранённым расширенным приложением, Qwen — более
систематизированная спецификация с явной классификацией требований и дефектов.
## 4. Модернизация и исправление дефектов

**Copilot** изменил 15 файлов. Подтверждённые по diff изменения:

- конфигурация секретного ключа, hosts, базы данных и Celery через переменные
  окружения с SQLite по умолчанию;
- переход от жёстко закреплённых зависимостей к совместимым диапазонам;
- более безопасное подключение Tinkoff SDK без обязательного импорта на старте;
- исправления сериализаторов/API и обработки данных рынка;
- миграция `0008_pricealert_pricealertnotification`.

**Qwen** изменил 64 файла и выполнил более широкий рефакторинг:

- конфигурация через окружение, SQLite по умолчанию, кастомная модель
  пользователя с email-аутентификацией;
- удаление проблемных SDK-зависимостей и добавление внутреннего REST-клиента
  Tinkoff на `requests`;
- отдельные permissions для API, исправления маршрутов, форм, шаблонов,
  обработки 404 и загрузки справочника;
- миграция `0008_watch_watchnotification_and_more` и миграция пользователя;
- структурирование логики мониторинга в отдельном сервисе.

Больший объём Qwen даёт более полную модернизацию, но увеличивает площадь
изменений и, следовательно, стоимость сопровождения и проверки. Copilot
сохраняет исходную структуру и вносит более локальные изменения.

## 5. Новая функциональность

Обе реализации добавляют персональные ценовые уведомления, но решения
различаются.

| Аспект | Copilot | Qwen |
|---|---|---|
| Модели | `PriceAlert`, `PriceAlertNotification` | `Watch`, `WatchNotification` |
| Условия | `above` / `below` | `gte` / `lte` |
| Приватность | API возвращает уведомления только владельцу | API и HTML показывают только записи владельца |
| Повторные срабатывания | `OneToOneField`, одно уведомление на условие | `last_triggered`, дедупликация срабатывания и повтор после сброса условия |
| Интерфейс | REST API | REST API и отдельные HTML-страницы |
| Тесты новой функции | 2 | 12 |

Обе функции реально подключены к обновлению цены. Qwen покрывает больше
сценариев, включая удаление, валидацию, приватность, отсутствие цены, сброс и
повторное пересечение порога. Copilot-решение проще, но его модель
предусматривает только одно уведомление за жизненный цикл условия.

## 6. Тестовое покрытие и независимая проверка

Проверки выполнены командами `python manage.py check`,
`python manage.py makemigrations --check --dry-run`,
`python manage.py migrate --noinput`, `python -m compileall -q .`,
`python manage.py test` и отдельным запуском HTTP-сервера.

| Проверка | `copilot-implementation` | `qwen-implementation` |
|---|---|---|
| Django check | Успешно, `0 issues` | Успешно, `0 issues` |
| Проверка миграций | `No changes detected` | `No changes detected` |
| Применение миграций | Успешно, dashboard `0001..0008` | Успешно, user `0001`, dashboard `0001..0008` |
| Тесты | **12/12 OK** | **25/25 OK** |
| `compileall` | exit `0` | exit `0` |
| HTTP smoke test `GET /` | HTTP `200` | HTTP `200` |

Для Qwen первый запуск до установки отсутствующей в текущем окружении
зависимости завершился `ModuleNotFoundError: requests`; `requests` присутствует
в его `requirements.txt` и был установлен перед повторной проверкой. После
этого все проверки прошли. Это ограничение исходного окружения, а не
доказательство падения ветки после установки заявленных зависимостей.

Заявления агентов о собственных финальных прогонах в целом совпали с
повторными результатами: Copilot заявлял 12 тестов, Qwen — 25 тестов, миграции,
`check`, `compileall` и HTTP 200. Время выполнения и число итераций из отчётов
не подтверждались и в сравнение как измеренные метрики не включаются.

## 7. Автономность и эффективность по доступным данным

Репозиторий подтверждает наличие двух отдельных веток, отдельных коммитов,
агентских отчётов и независимых наборов изменений. Он не позволяет независимо
доказать полную историю интерактивных сессий, точные промпты, затраченное время
или стоимость. Поэтому нельзя делать количественный вывод о скорости или
«лучшем» агенте.

По наблюдаемому результату Copilot эффективнее по объёму изменений и сохранил
более узкий scope. Qwen эффективнее по полноте анализа, количеству проверенных
сценариев и глубине модернизации. Это разные компромиссы, а не универсальное
превосходство одного инструмента.

## 8. Ограничения и сопровождаемость

- Оба решения используют старый проектный стек и внешнюю интеграцию с рынком;
  реальный Tinkoff API и Redis не проверялись, использовался локальный smoke
  test без внешнего сервиса.
- У Copilot меньше изменённых файлов и проще обратная проверка; новая функция
  ограничена базовым сценарием.
- У Qwen лучше разделены клиент Tinkoff, permissions и сервис мониторинга,
  есть HTML/API поверхности и более широкие тесты; одновременно присутствует
  больше переписанных шаблонов, настроек и пользовательской модели, что
  повышает регрессионный риск.
- Оба коммита содержат отчёты агента, но это самодокументирование, а не
  независимое подтверждение заявлений о процессе.

## 9. Итог

Обе реализации удовлетворяют базовой проверенной работоспособности и добавляют
ценовые уведомления. Copilot — более компактная и менее рискованная
модификация с 12 тестами. Qwen — более полная модернизация с детальным
восстановлением требований, расширенным UI/API и 25 тестами. Нейтральный выбор
зависит от цели: локальные изменения и сохранение исходной структуры либо
более глубокая модернизация и богатая функциональность.
