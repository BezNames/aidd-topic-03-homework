# Отчёт о работе с AI Coding Agents

## Текущая организация работы

- Исходная ветка: `main`.
- Ветка текущего прогона: `beznames-copilot-implementation`.
- Второй прогон выполняется в независимой сессии и отдельной ветке,
  созданной также от чистого `main`.
- Ветки не используют изменения друг друга.

## Промпты и итерации

Для текущего прогона использовались следующие этапы:

1. анализ структуры, архитектуры и фактических требований;
2. технический аудит конфигурации и зависимостей;
3. добавление персональных ценовых уведомлений;
4. запуск миграций, тестов и HTTP smoke test.

Ключевые дополнительные запросы были вызваны фактическими ошибками проверки:

- исходные фиксированные зависимости не устанавливались на Python 3.15 из-за
  старого `grpcio`, поэтому требования обновлены до совместимых диапазонов;
- импорт Tinkoff SDK на этапе проверки Django ломал запуск без SDK/токена, поэтому
  интеграции переведены на ленивый импорт с явной ошибкой при отсутствии токена.

## Проверки

- `python manage.py test` — 12 тестов успешно;

Добавлены тесты на создание наблюдения только для текущего пользователя и на
отсутствие повторных уведомлений для уже сработавшего условия.

# Investing Demo: анализ и восстановленные требования

## 1. Назначение приложения

Investing Demo — Django-приложение для ведения каталога биржевых акций. Оно
хранит основные идентификаторы инструмента, показывает список и карточку акции,
позволяет авторизованным пользователям изменять каталог, предоставляет REST API
и периодически обновляет текущую цену через Tinkoff Invest API.

## 2. Технологический стек

- Python и Django 4.1 (`requirements.txt`, `config/settings.py`).
- PostgreSQL как основная база данных (`config/settings.py`).
- Django REST Framework и django-filter для API
  (`requirements.txt`, `dashboard/api/v1/views.py`).
- Celery и Redis для фонового обновления цен
  (`requirements.txt`, `config/celery.py`, `dashboard/tasks.py`).
- Tinkoff Invest SDK для получения рыночных цен
  (`requirements.txt`, `dashboard/services/market_data.py`).
- Bootstrap 3 и crispy-forms для HTML-интерфейса
  (`requirements.txt`, `dashboard/templates`, `dashboard/forms.py`).

## 3. Структура и архитектура

`config` содержит настройки Django, маршрутизацию, WSGI/ASGI и конфигурацию
Celery. Приложение `dashboard` содержит доменную модель `Share`, HTML views,
формы, шаблоны, REST API, сервисы интеграции с Tinkoff и фоновые задачи.
Приложение `user` отвечает за регистрацию и аутентификацию.

HTML-запрос проходит через `config/urls.py` и `dashboard/urls.py` в class-based
view. API-запрос проходит через router из `dashboard/api/v1/router.py` в
`ShareViewSet`, сериализуется `ShareSerializer` и работает с ORM-моделью `Share`.
Celery-задача `update_last_price` получает акции из БД, вызывает
`dashboard.services.market_data.get_last_data`, а затем записывает цену и
направление тренда.

## 4. Модель данных

Единственная основная бизнес-сущность исходной версии — `Share`
(`dashboard/models.py`):

- `figi` — уникальный идентификатор инструмента;
- `isin` — международный идентификатор;
- `name` — название компании;
- `ticker` — уникальный тикер;
- `currency` — валюта;
- `uid` — уникальный идентификатор Tinkoff;
- `last_price` — последняя полученная цена;
- `is_trend_high` — признак роста относительно предыдущей цены;
- `updated_at` — время последнего изменения записи.

В исходной версии связей с пользователем, портфелем, историей цен или
уведомлениями нет.

## 5. Фактически реализованная функциональность

1. Система отображает отсортированный по имени список акций
   (`dashboard/views.py`, `ShareListView`).
2. Пользователь может открыть карточку акции и увидеть её график
   (`dashboard/views.py`, `ShareDetailView`).
3. Аутентифицированный пользователь может создать акцию
   (`dashboard/views.py`, `ShareCreateView`).
4. Аутентифицированный пользователь может редактировать акцию
   (`dashboard/views.py`, `ShareUpdateView`).
5. Аутентифицированный пользователь может удалить акцию
   (`dashboard/views.py`, `ShareDeleteView`).
6. REST API поддерживает список, получение, создание, изменение и удаление
   акций через `ShareViewSet` (`dashboard/api/v1/views.py`).
7. API поддерживает фильтрацию по `name` и `ticker`, поиск по названию и
   сортировку по `name` и `ticker` (`dashboard/api/v1/views.py`).
8. Фоновая задача получает последнюю цену каждой акции через Tinkoff Invest API
   и обновляет `last_price` и `is_trend_high`
   (`dashboard/tasks.py`, `dashboard/services/market_data.py`).
9. Команда `add_shares` загружает первоначальный список акций
   (`dashboard/management/commands/add_shares.py`).
10. В приложение включены регистрации и аутентификация пользователей
    (`user/views.py`, `user/urls.py`, `config/settings.py`).

## 6. Ограничения и неоднозначности исходной версии

- Токен Tinkoff и `SECRET_KEY` заданы прямо в settings и имеют пустые значения.
- Основная БД жёстко настроена на PostgreSQL на localhost, поэтому локальный
  запуск без PostgreSQL не гарантирован.
- В `ShareDetailView` используется прямой `Share.objects.get`, поэтому
  несуществующий идентификатор приводит к исключению вместо контролируемого 404.
- Обновление цены предполагает, что ответ Tinkoff содержит хотя бы один элемент.
- В исходном коде нет пользовательских инвестиционных данных, уведомлений и
  истории цен; они не являются требованиями исходной версии.
- Поведение Celery зависит от внешних Redis и Tinkoff API, поэтому для тестов
  внешний API должен быть заменён mock-объектом.

## 7. План изменений

Модернизация должна исправить конфигурацию и обработку ошибок без потери
исходного CRUD/API. Дополнительная функциональность реализуется отдельно:
персональное наблюдение пользователя за акцией с целевой ценой, автоматической
проверкой условия при обновлении цены и дедупликацией уведомлений об одном
событии.
